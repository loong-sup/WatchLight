# 飞书群聊多用户会话隔离 Spec

## 背景

当前飞书群聊中的所有成员共用同一个群级会话。消息记录只包含通用的 `user`
角色和消息正文，无法区分不同发送者；飞书用于表示被提及对象的占位符还会以
`@_user_1` 等形式进入消息正文。这会造成不同成员的模型上下文串线，并降低会话
记录的可读性。

## 目标

- 同一个飞书群中的不同发送者使用彼此独立的模型会话和 transcript。
- 同一发送者在同一群中的后续消息继续使用自己的既有会话。
- 回复仍发送到原群聊，并继续遵守群聊必须明确提及机器人的策略。
- 写入模型上下文前清除机器人的飞书提及占位符。
- 保持任务数据现有的用户级隔离行为。

## 功能需求

- F1：群聊会话必须同时以通道、群聊和发送者身份确定；任一发送者不同，都不得
  复用另一发送者的会话。
- F2：私聊会话路由行为保持不变。
- F3：系统必须根据飞书事件中的提及信息识别并移除机器人提及占位符，不将
  `@_user_1` 等机器人占位符写入模型上下文或 transcript。
- F4：群聊消息记录必须保留可追溯的发送者标识，便于诊断消息属于哪个用户。
- F5：改变路由后，回复目标仍是原群聊，且任务创建、查询、删除仍使用发送者的
  独立用户身份。
- F6：历史群级共享会话必须保留，不自动删除或错误迁移；新消息开始写入新的
  用户级群聊会话。

## 非功能需求

- N1：会话键必须稳定、确定，服务重启后同一群和同一发送者仍映射到同一会话。
- N2：不得因为会话隔离泄露其他成员的历史消息或任务数据。
- N3：兼容飞书原始事件、当前内部 sidecar 事件和不含提及数组的消息。
- N4：现有私聊、Web 会话和任务自然语言流程不得回归。

## 不做的事

- 不把群聊历史共享会话拆分或迁移到各个成员，因为旧记录没有可靠的发送者元数据。
- 不改变群聊的可见性；机器人回复仍然对整个群可见。
- 不实现群内共享知识库、跨成员协作上下文或管理员查看他人私有会话。
- 不改变飞书应用发布、权限或外部群配置。

## 验收标准

- AC1：同一群的用户 A 和用户 B 交替发送消息后，生成两个不同会话，双方 transcript
  不包含对方消息。
- AC2：用户 A 在同一群连续发送两条消息时，两条消息进入同一会话。
- AC3：同一用户在两个不同群发送消息时，生成两个不同会话。
- AC4：私聊会话键及上下文延续行为保持现状。
- AC5：带机器人提及的飞书群消息进入 transcript 后，不包含机器人对应的
  `@_user_N` 占位符；普通正文保持不变。
- AC6：每条新群聊用户记录都能观察到其飞书发送者标识。
- AC7：两个群成员分别创建或查询任务时，只访问各自任务，并且回复均发送到原群聊。
- AC8：现有测试、新增隔离测试和代码规范检查全部通过。
