# Watchlight 主工作台视觉与观测体验升级 Plan

> 输入：`docs/frontend-workbench-redesign/spec.md`（已批准）

## 架构概览

继续使用现有 Vue 3、Pinia 和单页三栏结构，不增加第三方 UI 依赖。全局视觉变量和页面框架由主入口统一管理；现有业务组件分别承担会话导航、执行链路、运行时间线、消息输入和检查器展示。观测指标由当前 Pinia store 中已有的活动运行、事件和工具数据即时派生，不进入持久化层。

## 核心派生数据

### WorkbenchMetric

- `label`：指标名称。
- `value`：当前显示值。
- `hint`：指标语境或状态说明。
- `tone`：用于区分普通、活动、成功和异常状态的视觉语义。

### InspectorVisibility

- 主入口维护检查器显隐状态。
- 宽屏默认显示，用户可通过顶栏按钮切换。
- 中等宽度默认优先保证主链路宽度，隐藏检查器后可再次打开。

### LayerProgress

- 继续使用现有七层架构状态。
- 每个节点根据 `idle | active | done | failed` 得到形态、文案和光迹状态。
- 光迹由 CSS 连接线与伪元素完成，不改变运行事件结构。

## 模块设计

### 主工作台框架

**职责：** 提供设计变量、品牌顶栏、概览指标、三栏布局和检查器显隐控制。  
**依赖：** 当前运行 store 和所有现有工作台组件。

### 会话导航

**职责：** 展示连接摘要、通道数量、会话选择和刷新动作；强化活动会话状态与内容层级。  
**依赖：** 当前运行 store。

### 架构光迹

**职责：** 展示七层执行路径、当前位置、节点状态、最近事件和连续光迹。  
**依赖：** 现有架构层定义与活动事件。

### 运行时间线

**职责：** 分层展示输入、工具、输出、回写和底层事件；提供运行级状态摘要。  
**依赖：** 活动运行与活动事件。

### 检查器

**职责：** 展示最终输出、工具结果、消息上下文及其数量；在主框架控制下显示或隐藏。  
**依赖：** 活动运行、工具面板和消息上下文面板。

### 消息输入

**职责：** 保持原发送流程，升级输入、状态提示、快捷键提示和按钮反馈样式。  
**依赖：** 当前运行 store。

## 模块交互

```text
runtime store
   ├─ 主框架派生顶部指标
   ├─ 会话导航选择 activeRun
   ├─ 架构光迹派生七层状态
   ├─ 时间线展示 activeRun/events/tools
   └─ 检查器展示 output/tools/messages

用户选择会话 → activeRun 更新 → 指标、光迹、时间线、检查器同步刷新
用户切换检查器 → 只改变布局显隐 → 不改变运行数据
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 视觉实现 | CSS 变量与组件 scoped CSS | 保持零新增依赖并兼容现有工程 |
| 图标 | 内联 SVG | 图标数量少，可统一描边语言并避免依赖 |
| 指标来源 | 从活动运行即时派生 | 满足第一轮观测需求且无需修改后端 |
| 光迹 | CSS 连接线、渐变和动画 | 与七层状态自然结合，性能开销低 |
| 检查器适配 | 显隐切换 + 响应式隐藏 | 优先保护主链路阅读空间 |
| 动效无障碍 | `prefers-reduced-motion` | 尊重系统设置并满足规格要求 |

## 自检

- F1 至 F10 均有明确模块归属。
- 不修改 store 数据契约、后端接口或教学页。
- 模块依赖均指向现有 store，不产生新的循环依赖。
