# 飞书自然语言删除关注任务 Spec

## 背景

Watchlight 已支持通过飞书自然语言创建、确认和查询关注任务，后端也已有按任务 ID 删除的业务能力。但飞书用户目前无法在对话中完成删除，只能先调用列表 API 获取任务 ID，再调用 REST 删除接口。删除属于高影响写操作，不能仅凭模糊任务名称立即执行，需要提供可识别的候选列表、名称关键词消歧和明确的二次确认。

## 目标

- 用户能够直接在飞书中发送“删除任务”发起删除流程。
- 系统展示当前可删除任务的名称、状态和任务 ID，允许用户用任务名称关键词或完整任务 ID 选择。
- 名称关键词匹配多个任务时，系统展示匹配候选并要求继续消歧，不做猜测。
- 唯一候选确定后，系统展示将删除的任务及影响，只有收到明确“确认删除”才提交删除。
- 删除流程严格绑定当前用户与当前会话，防止跨用户、跨会话或过期确认造成误删。

## 功能需求

- F1：用户发送“删除任务”“删除关注任务”或语义等价的明确删除指令时，系统必须进入删除流程并展示当前用户所有可删除任务。
- F2：候选列表必须展示任务名称、当前状态和完整任务 ID，并提示用户回复任务名称关键词或完整任务 ID。
- F3：用户回复名称关键词时，系统必须仅在当前用户可删除任务中进行不区分大小写的包含匹配；完整任务 ID 必须采用精确匹配。
- F4：匹配结果为零时，系统必须说明未找到并保留删除流程，允许重新输入关键词；匹配结果超过一个时，必须展示全部匹配候选并要求继续消歧。
- F5：匹配结果唯一时，系统必须展示唯一任务的名称、任务 ID、当前状态，以及删除会停止后续执行和通知的影响，并提示回复“确认删除”或“取消”。
- F6：只有处于待确认删除状态且用户回复完全一致的“确认删除”时，系统才能提交删除；普通“确认”“确定”“删除”不得执行。
- F7：用户回复“取消”或“取消删除”时，系统必须清除当前删除流程且不修改任何任务。
- F8：待选择和待确认状态必须绑定规范用户身份、渠道会话和候选任务；超过 10 分钟自动失效，失效后必须重新发起删除流程。
- F9：提交删除前必须重新读取任务并校验任务仍属于当前用户且仍可删除；校验失败时不得执行，并清除或安全重置当前流程。
- F10：删除提交成功后，系统必须明确回复任务已进入删除流程；任务随后沿用现有 `draining → deleted` 状态收敛，不产生新的周期执行或通知。
- F11：删除流程中的用户输入和系统回复必须写入同一飞书/Web 会话历史，便于后续追问和审计。
- F12：Web 对话入口必须复用同一删除语义，确保渠道行为一致；飞书为本次主要端到端验收入口。

## 非功能需求

- N1：所有列表、匹配、复核和删除操作必须使用现有按用户隔离的数据访问层，不允许模型或用户消息覆盖规范用户身份。
- N2：模糊名称匹配只能用于选择候选，不能直接跳过二次确认。
- N3：删除流程必须为确定性业务流程，不依赖大模型是否正确理解或调用写工具。
- N4：删除确认状态只保存在进程内短期会话状态中；服务重启后确认失效，不得恢复并自动执行。
- N5：重复发送“确认删除”必须是幂等安全的；第一次成功后删除状态被清除，后续确认不得再次执行。
- N6：不得扩大飞书远程工具权限，不新增可由模型自由调用的删除写工具。
- N7：现有创建、确认、查询、调度、身份隔离和 REST 删除行为保持兼容。

## 不做的事

- 本次不支持批量删除多个任务。
- 本次不支持“删除全部任务”。
- 本次不支持根据序号直接选择任务；用户使用名称关键词或完整任务 ID。
- 本次不支持撤销已经提交的删除请求。
- 本次不改变 `draining → deleted` 的调度收敛规则和审计保留策略。
- 本次不增加暂停、恢复或修改任务的自然语言流程。

## 验收标准

- AC1：飞书用户发送“删除任务”后看到自己的可删除任务名称、状态、完整任务 ID和选择提示。
- AC2：输入唯一名称关键词后看到明确的待删除摘要；输入重复名称关键词时看到多个候选且任务状态不变；继续输入更精确关键词或完整任务 ID后得到唯一候选。
- AC3：在待确认状态回复“确认”“删除”或其他文本均不删除；只有“确认删除”会使目标任务进入 `draining`。
- AC4：回复“取消”后任务保持原状态；确认超过 10 分钟、换会话确认或重复确认均不执行删除。
- AC5：用户 A 无法看到、匹配或删除用户 B 的任务，即使提供 B 的完整任务 ID也失败且不泄露任务详情。
- AC6：确认前任务已被删除、正在删除或状态发生不可删除变化时，复核失败且不会产生额外状态变更。
- AC7：飞书完整流程“发起 → 关键词消歧 → 唯一候选 → 确认删除 → 调度收敛”通过，最终普通任务列表不再返回该任务，也不生成新的 pending execution。
- AC8：删除相关对话按顺序写入同一 transcript，现有创建、查询、身份隔离、调度和 REST API 测试继续通过。
