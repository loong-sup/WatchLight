# 任务意图理解与纠正 Spec

## 背景

当前任务创建只识别少量关键词，并把完整命令作为关注目标和搜索词。它无法识别
“每隔 5 小时”等常见表达，也无法在用户纠正后更新既有目标和来源字段。

## 目标

- 将自然语言解析为受约束的任务意图和字段补丁。
- 支持用户对待确认草稿进行增量纠正。
- 所有模型结果必须经过确定性校验后才能展示或持久化。
- 模型不可用时仍能处理核心中文表达。

## 功能需求

- F1：区分创建、修改、确认、取消、查询和非任务意图。
- F2：提取简洁关注目标、来源、触发条件、执行间隔和通知渠道，不把命令全文当目标。
- F3：支持每隔 N 分钟、小时、天及每天、每小时表达，并遵守现有 15 分钟至 7 天范围。
- F4：待确认期间的新表达只覆盖明确修改的字段；“不是 X，是 Y”采用 Y。
- F5：完整重述任务时更新目标、来源、频率和通知字段，不保留旧命令文本。
- F6：模型仅输出结构化意图；未知字段、非法类型、越界频率和危险操作由代码拒绝。
- F7：模型失败、超时或输出非法时使用确定性解析降级。
- F8：固定钟点、周历等当前调度器无法表达的计划必须澄清，不得错误降级为每天。
- F9：修正已生成的待确认任务时更新同一个暂停任务及版本，不产生孤立重复任务。

## 非功能需求

- N1：现有查询、删除、私聊、群聊和 API 任务流程保持兼容。
- N2：模型解析不得直接写数据库或调用外部工具。
- N3：解析失败必须可观测并安全降级。
- N4：字段合并和校验结果可通过单元测试复现。

## 不做的事

- 不在本次增加 Cron、固定时间点或工作日调度数据库字段。
- 不让模型绕过任务确认或安全限制。
- 不自动修正无法确认的产品、公司或专有名词。
- 不持久化尚未确认的聊天草稿。

## 验收标准

- AC1：“关注小米公司的澎程汽车，每隔5小时，飞书通知”得到简洁目标和 18000 秒频率。
- AC2：“不是每五小时，是每天”只把草稿频率改为 86400 秒，确认摘要不再出现旧频率。
- AC3：用户完整重述任务后，目标和搜索关键词同步更新。
- AC4：模型返回未知字段、非法频率或非法 JSON 时不污染草稿，并自动降级或追问。
- AC5：固定时间表达得到明确澄清，不创建错误任务。
- AC6：连续纠正只更新同一暂停任务，不增加额外任务行。
- AC7：现有测试、新增测试和代码规范检查全部通过。
